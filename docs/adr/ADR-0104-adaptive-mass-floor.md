# ADR-0104: Адаптивный пол каскада по накопленной важности (`refine_min_mass`)

- **Статус:** Accepted (реализован — 2026-07-07)
- **Дата:** 2026-07-07
- **Драйверы:** D-2 (страховка от прокси-слепоты), D-3 (estimator-agnostic), D-4 (a-priori cost).
  Источник: FR-3, NFR-3, NFR-5. Amendment к ADR-0100.

## Контекст

Non-inferiority (ADR-0103) **не ловит прокси-слепоту**: если estimator-agnostic ExtraTrees
честно не видит разницы между 5 и 68 фичами (adult), bootstrap-CI узкий вокруг нуля, margin-тест
проходит, а отгружаемые бустеры теряют −2.2 п.п. AUC. Нужна страховка через **распределение
сигнала стадии 1**, а не статистику скорингов прокси. Ручной референс: `CUM_IMPORTANCE=0.99`
(кумулятивная доля важностей). `agg` — L1-нормированный по фолдам вектор важностей — **уже
посчитан** в `_select_one` (research Q6), доступен без доп. фитов.

## Рассмотренные варианты

1. **Пол по кумулятивной массе `agg`** (`refine_min_mass`): спуск не ниже `k` топ-признаков,
   покрывающих долю mass. Плюсы: 0 фитов, детерминизм от `agg`, адаптивен к распределению
   сигнала (доминанта ⇒ низкий пол; размазано ⇒ высокий). Минусы: `agg` знаковый у
   random_probe/null_importance ⇒ нужна нормировка (R-3).
2. **Статический пол-константа.** Отвергнут: «для titanic 1 фича легитимна, для adult 5 вредны —
   подходящей константы не существует» (R5).
3. **Скоринг траектории лидером (F145).** Отвергнут: ломает estimator-agnostic (ADR-0043 §4),
   ~150-500 бустинг-фитов — Out of scope (Day-2).

## Решение

**Вариант 1.** Новое поле `FeatureSelectionConfig.refine_min_mass: float` (**домен `0 ≤ x ≤ 1`;
`0` = mass-floor ВЫКЛ (opt-in-нейтраль)**, дефолт-кандидат ~**0.99** — совпадает с валидированным
ручным `CUM_IMPORTANCE=0.99`; 0.95 слабее (ниже пол, легче недоотсечь) — ревью). В `_select_one`
(до входа в каскад), из уже вычисленного `agg`:

```
if refine_min_mass <= 0.0:                  # off: mass-floor не поднимает пол
    mass_floor = 0
else:
    pos = np.clip(agg, 0.0, None)           # R-3/NFR-5: знаковый agg -> неотрицательная масса
    total = pos.sum()
    if total == 0.0:                         # сигнала нет -> mass-floor не активен
        mass_floor = 0
    else:
        frac = np.sort(pos)[::-1].cumsum() / total
        mass_floor = int(np.searchsorted(frac, refine_min_mass) + 1)  # мин. k, покрывающих mass
```
**Детерминизм searchsorted (minor ревью):** на пограничном `agg` FP-округление `frac[k]` у порога
может флипнуть `mass_floor` на ±1 между платформами (тот же класс, что чинили для boosting,
ec1e4ba). Правило: применить малый `atol` (напр. `refine_min_mass − 1e-12`) в сравнении, чтобы
граница была детерминирована по построению; закрепить кросс-платформенным тестом при реализации.

`mass_floor` входит в унифицированный пол (ADR-0105): `floor = max(min_features,
seq_min_features, mass_floor)`. Прогноз по кейсам (research/R5): titanic — `Sex_freq`
доминирует ⇒ `mass_floor` низкий (легитимная 1 фича сохранена); adult — масса размазана по
TE-энкодингам ⇒ `mass_floor` ~10-15 (сценарий «5 фич» отсечён); ieee/home-credit — почти без
изменений.

**A-priori cost (D-4/NFR-3):** `mass_floor` **данно-зависим** (через `agg`), но он лишь
**поднимает** пол ⇒ **укорачивает** траекторию. Поэтому `estimate_fs_refits`/`_refine_steps`
считает по **статическому** полу `max(min_features, seq_min_features)` (a-priori), и фактическая
траектория ≤ оценки — оценка остаётся валидной **верхней границей**. `mass_floor` в cost-модель
**не добавляется** (иначе оценка стала бы data-dependent, нарушив NFR-FSF-1).

**Независимость от significance:** mass-floor — страховка от прокси-слепоты, работает и при
`significance="off"` (в отличие от non-inferiority, FR-6): пол применяется к траектории всегда
при `refine=True`.

## Последствия

- **Положительные:** снижает риск прокси-слепоты (adult) через распределение сигнала, а не
  статистику скорингов прокси; ноль доп. фитов; детерминизм; ручка `refine_min_mass` — прямой
  аналог проверенного ручного `CUM_IMPORTANCE`.
- **Отрицательные / компромиссы:**
  - **Эвристика, не гарантия (Major-2 ревью).** `mass_floor` считается из ТОЙ ЖЕ ExtraTrees-важности,
    что признана прокси-слепой: **концентрация важности ≠ предсказательная разница**. Механизм
    работает, ЕСЛИ вредный over-prune случается при *размазанной* важности (гипотеза для adult), и
    НЕ поможет, если прокси концентрирует важность в предиктивно-недостаточных фичах. Полное лекарство
    — F145 (скоринг лидером), **вне scope** (Day-2). ⇒ Эффективность на adult/titanic — **эмпирическое
    допущение** (наблюдение R5: adult размазан ⇒ пол ~10-15; titanic `Sex_freq` доминирует ⇒ пол
    низкий), **не воспроизведённое в артефакте** (R-6: `model_utils.py` отсутствует). **Обязательный
    acceptance-гейт РЕАЛИЗАЦИИ:** перепрогон adult+titanic showcase подтверждает
    `mass_floor(adult) > 5` (закрывает −2.2 п.п.) и что легитимный компактный размер titanic не
    запрещён; при опровержении — ретюн дефолта/пересмотр (не блокер дизайна — механизм статкорректен).
  - **R-3:** на знаковом `agg` масса по клампнутому неотрицательному; all-zero ⇒ `mass_floor=0`
    (не активен) — пол не «взрывается» и не опускается.
  - **mass_floor — пол ТОЛЬКО спуска, не жёсткая нижняя граница отгрузки (minor ревью):** если
    coarse-cutoff уже дал `len(subset1) < mass_floor`, short-circuit грузит `subset1` (ниже
    mass_floor). Для целевого adult (subset1≈14) страховка работает; как абсолютный пол —
    не гарантия. Документировать в FR-7-наблюдаемости.
  - **Семантика дефолта (Major-1 ревью, исправлено):** нейтраль (mass-floor выкл) = **`refine_min_mass=0`**
    (домен `0 ≤ x ≤ 1`), НЕ `1.0` (последнее ⇒ пол ≈ число положит. фич = почти-нет-прунинга,
    эффект ОБРАТНЫЙ). «ON vs opt-in» и точный дефолт — **релизное решение владельца**.
  - Data-dependent пол ⇒ выбор размера зависит от `agg` — но cost-оценка остаётся a-priori (см.
    выше). Fingerprint-чурн (`refine_min_mass` в конфиге) — NFR-6.
- **Влияние на слои/границы:** чистая арифметика над `agg` в `application` (feature_selection/
  feature_compare); порты и adapters не трогаются. Import-linter KEPT.

## Проверки
- FR-3: тест mass-floor на профиле «доминанта» (низкий пол) и «размазано» (пол ~10-15).
- NFR-5: тест на знаковом `agg` (отрицательные значения) и all-zero-после-клампа.
- NFR-3: тест `estimate_fs_refits ≥ len(actual_trajectory)` при активном `refine_min_mass`.
- Детерминизм: mass_floor — чистая функция `agg` (двойной вызов идентичен).
