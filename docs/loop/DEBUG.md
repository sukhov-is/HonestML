# HonestML Debug Loop — контракт одного раунда (разрешение находок аудита)

Один раунд. Свежий контекст; память — файлы и git-история. Прочитай состояние, продвинь **ОДНУ
единицу работы** аудита подходящим воркфлоу на один **шаг маршрута** — путь честности идёт находкой,
всё остальное группой (§1), — запиши исход, закоммить, выйди. Следующий раунд запустит драйвер.

**Шаг маршрута — это DESIGN или IMPLEMENT целиком (§2), а не часть от них.** Milestone плана,
срез пакета, «одна из четырёх частей» — границы внутри раунда, а не границы раунда. Цель шага —
закрыть находку, а не продвинуть её: IMPLEMENT кончается тем, что бага больше нет.

**Назначение:** довести пакет аудита до состояния «каждая находка исправлена или осознанно отложена».
Каждую находку петля **маршрутизирует по природе фикса**:
- нужен редизайн (новая структура/слой/контракт/durable-компонент) → `architecture-design` → `implementation`;
- локализованный баг с известной причиной, нужна строгая верификация → `targeted-fix`;
- мелкая нетоведенческая правка (доки, комментарии, мёртвый код) → чинит сама.

**Целевой пакет:** свежайший `docs/audit/<дата>/` — реестр `02-ledger.md` (находки `F-xx`: severity,
якорь `file:line`, вердикт-заметка), приоритизация с рекомендованным маршрутом
`04-roadmap.md`, прогресс `05-fixes.md`. Второй допустимый вход — реестр аудит-петли
`docs/audit/loop/findings.md`: приоритет берётся из колонки severity самой строки, маршрут — по
классификации §1 (собственного roadmap у аудит-петли нет), прогресс — `docs/audit/loop/05-fixes.md`
того же формата (§3). Полное доказательство живёт в досье аудитора
`01-findings/<отчёт>.md`, на который ссылается строка реестра; принятые as-is компромиссы — в
`docs/audit/learnings.md` и дизайн-пакетах `docs/architecture/<пакет>/`. **Решения владельца,
вписанные в вердикт-заметки реестра и в `04-roadmap.md`, финальные: не переспрашивать и не
пересматривать.**
**Контур поднимает человек** — отдельным прогоном драйвера по этому контракту. Петля пишет код в
основной копии и коммитит на каждый шаг, поэтому **запускать её только при остановленной dev-петле**,
с которой она делит рабочий каталог.

## Жёсткие границы

- **Дефолт классификации — `targeted-fix`; `design` — эскалация по структурному признаку, не по сомнению.**
  Любое изменение **поведения** идёт в `targeted-fix`; строгая верификация не теряется, потому что
  `doubt-driven-development` на пути честности раунд запускает сам. В `design` уходит только находка с **конкретным
  структурным признаком** (§1: новый порт в `honestml.core.ports`, новая запись в allowlist
  `.importlinter`, новая версия персистентного контракта с миграцией, новый durable-компонент, либо
  изменение существующего контракта). Сомнение «фикс или редизайн» само по себе → `targeted-fix`; он
  вернёт `route:design`, если по ходу упрётся в необходимость новой структуры. Сомнение «мелкая или
  нужна верификация» → `targeted-fix`. Маршрут «сама» — только для правок, не меняющих поведение
  исполняемого кода.
- **Путь честности** — всё, от чего зависит честность оценки: CV-сплиты с purge/embargo и
  group-disjoint, кросс-фитовый таргет-энкодинг, отбор признаков и его gate, калибровка на OOF,
  honest holdout, finalize-refit, политика выбора модели (значимость, размер каскада), миграция
  персистентного контракта (`ModelArtifact`/`RunManifest`) и десериализация артефакта. Находка на нём
  закрывается только с пройденным `doubt-driven-development`, и запускает его раунд явным вызовом —
  по всему этому списку и на любом маршруте. По маршруту design адверсариальную проверку дополнительно несёт
  фаза Design Review скила `architecture-design`; фаза Review скила `implementation` собственной
  адверсариальной проверки не содержит.
- Меняй только то, что относится к выбранной находке (+ её тест/дизайн-пакет + `05-fixes.md`). Никакого
  рефактора «рядом» и правок других находок в одном раунде.

## 0. Ориентация (дёшево, сначала)

1. Есть `docs/audit/<пакет>/DONE` — пакет уже закрыт: выйди немедленно, ничего не делая.
2. Прочитай `05-fixes.md` (что закрыто / отложено / в процессе; нет файла — заведи по формату §3),
   `02-ledger.md` (реестр: `F-ID`, severity, якорь `file:line`, вердикт-заметка) и `04-roadmap.md`
   (приоритет и рекомендованный маршрут). За полным доказательством иди в досье `01-findings/`.
3. Условие остановки (§4) выполнено → §5.

## 1. Выбор находки и маршрут

- **Сначала добей WIP** (незавершённые статусы из `05-fixes.md`):
  - `designed` (дизайн готов, кода нет) → IMPLEMENT-шаг маршрута design (§2a, п. IMPLEMENT).
  - `route:design` (перемаршрутизирована в дизайн) → DESIGN-шаг (§2a, п. DESIGN).
  - `route:fix` (перемаршрутизирована в targeted-fix) → §2b.
- Иначе бери самую приоритетную неразрешённую находку (**Critical → High → Medium → Low**; внутри
  severity — путь честности раньше; при равенстве — порядок реестра; семейства и бандлы — по пометкам
  в `05-fixes.md`, если их завёл прошлый раунд). Находку, которой раунд при разборе проставил в
  `05-fixes.md` пометку **`blocked-by:<id>`**, не бери, пока её блокер не `fixed`. Находка с
  пометкой **req-предшаг** проходит `requirements-planning` (дельта FR/NFR, ревизия trade-off) перед
  DESIGN-шагом — допустимо в том же раунде, коммит один.
- **Гранулярность (вне пути честности батч обязателен):**
  - **Critical и ЛЮБАЯ находка пути честности** (утечка в CV, отбор признаков, калибровка, honest
    holdout, политика выбора, миграция контракта артефакта) — по **одной** находке за раунд: нужен
    фокус, часто design→impl, обязательный doubt-driven.
  - **High вне пути честности** (архитектура, наблюдаемость, надёжность, доки) — **группа 2–3**
    связанных находок одного маршрута из одной зоны/модуля.
  - **Medium/Low вне пути честности** — **группа 8–10** (все `trivial` вместе; небольшие `fix`
    вместе) из одной зоны; готовые бандлы — по пометкам в `05-fixes.md`. Одиночную находку этого класса
    бери только когда совместимых в реестре не осталось, и назови в леджере причину.
  - **Системные корни** чини как ОДИН корневой фикс на все сайты, а не поточечно: инициализация
    OOF-буфера, продублированная в `oof_scorer.py`/`feature_compare.py`/`slice.py` (F050), — это одна
    находка-раунд, покрывающая все инстансы, а не три строки реестра. Перед фиксом grep'ом собери
    остальные сайты того же паттерна.
  - В группе каждая `fix` получает свой red-green тест, но **гейты гоняются один раз на всю группу**,
    коммит — **один** (`fix(<id>,<id>,…): <кратко>`), строки всех находок группы — в `05-fixes.md`.
    Находка, оказавшаяся `design`-route или fix-failed, выделяется отдельно — не топит группу.
- **Пропусти сразу** (`deferred:<класс>`, воркфлоу не зови): **TRADE-OFF / REJECTED / Спорно** —
  задокументированные и отклонённые, это не баги; **ОТЛОЖЕНО решением владельца** и всё, что стоит
  в секции «Не делать сейчас» файла `04-roadmap.md`, — `deferred:owner`.
- **Классифицируй остальное** — дефолт `fix`, `design` только по структурному признаку:
  - **`fix` (маршрут по умолчанию для изменения поведения)** — локализованный баг с установленной
    причиной; строгую верификацию несёт targeted-fix (Confirm → root → red-green → гейты) плюс
    `doubt-driven-development` на пути честности. Сюда идёт всё, что не подпадает под структурный триггер
    `design` и не является нетоведенческой правкой `trivial` — большинство correctness- и
    security-находок реестра. → §2b.
  - **`design` (эскалация — только при конкретном структурном признаке)** — фикс **вводит новую
    durable-структуру** (новый порт в `honestml.core.ports`, новая запись в allowlist `.importlinter`,
    новый компонент композиции) **либо меняет существующий контракт** (персистентный формат
    `ModelArtifact`/`RunManifest` и его версия, публичный API фасада, контракт плагина
    `docs/plugin-contract.md`, сигнатура существующего порта).
    Переиспользование существующей конвенции без новой структуры (δ0 порта/контракта/`.importlinter`)
    — **не** `design`, а `fix`. → §2a.
  - **`trivial`** — правка, не меняющая поведение исполняемого кода: текст доков и ADR, лгущий
    комментарий, мёртвый код/конфиг-ключ, чистое переименование. → §2c.

## 2a. Маршрут `design` (architecture-design → implementation)

- **DESIGN-шаг.** Вызови скил **`architecture-design`** по находке (дизайн-пакет
  `docs/architecture/<fix-slug>/`, до design-gate). Передай `file:line` + вердикт-заметку реестра и
  доказательство из досье `01-findings/`. Если у находки помечен req-предшаг — сначала `requirements-planning`.
  - **Контур design-review — лёгкий** (пара ревьюеров + верификатор закрытия). **Полный** (два раунда
    fan-out) — только когда срез несёт семантику пути честности либо меняет существующий персистентный
    или публичный контракт. Новый порт или адаптер сам по себе полного контура не требует.
  - **Пакет режь по размеру импл-раунда.** IMPLEMENT закрывает его целиком, поэтому дизайн,
    который заведомо туда не влезает, делится здесь — на находки со своими строками реестра,
    каждая со своим самостоятельным исходом. Ориентир — тот же, что у основной петли
    (`LOOP.md` §2a, «Размер среза»); делить после, на импл-шаге, уже поздно.
  - gate **go** → коммит `fix-design(<id>): <кратко>`, статус `designed`; дизайн-пакет лежит под
    git-ignored `docs/architecture/`, поэтому индексируй его принудительно — `git add -f docs/architecture/<fix-slug>`.
    Заверши раунд — impl отдельным.
  - нужен вопрос только-пользователю → `deferred:design-blocked`, причина, коммит. Промежуточный
    **no-go** гейта раунд закрывает сам: вернись к нужной фазе скила, устрани и повтори гейт.
- **IMPLEMENT-шаг** (следующий раунд по `designed`-находке). Вызови скил **`implementation`** по
  дизайн-пакету (Plan → Tests → Impl → Review → DoD). Шаг закрывает пакет **целиком** — все
  milestone'ы `08-plan.md` и все строки матрицы, — потому что находка либо исправлена, либо нет;
  «сделал два среза из четырёх» исходом не является и статуса под себя не имеет. DoD — один
  foreground-вызов `powershell -NoProfile -File ops/loop/gates.ps1` с таймаутом 2700000 ms (45 минут);
  он судит весь набор гейтов проекта: loop-contract, skill-parity, instruction-parity, config-check,
  registers, check-index, ruff-format, ruff, lint-imports, mypy, pre-commit, pytest. Раунд закрывает
  `-Scope Full` (значение по умолчанию); по ходу итераций годятся `-Scope Fast` (добавляет pytest
  `-m "not slow"`) и точечный `uv run pytest <путь> -q`.
  DoD зелёный (с фактическим выводом гейтов) → коммит `fix(<id>): impl — <кратко>`, статус `fixed`.
  DoD красный после ретраев → `fix-failed`, причина.
  - Пакет не помещается в раунд — это дефект дизайна, а не исход импл-шага: статус
    **`route:design`**, причина называет закрытые milestone'ы и оставшиеся. Следующий DESIGN-раунд
    режет остаток на находки, каждая из которых закрывается за раунд. Незакрытый пакет под
    статусом `designed` не оставляй: реестр станет утверждать «кода нет» про находку,
    реализованную наполовину, — а `fix-failed` финален (§4) и бросит остаток совсем.
  - **Бюджет Review:** путь честности или новая граница — четыре линзы отдельными параллельными
    субагентами; остальное — один свежий ревьюер по всем четырём измерениям.

## 2b. Маршрут `fix` (targeted-fix)

- Вызови скил **`targeted-fix`** по находке (`file:line` + вердикт + направление фикса). Он ведёт
  Confirm → Fix root → red-green регресс-тест → Verify (гейты); на пути честности раунд добавляет
  `doubt-driven-development` явным вызовом.
  - гейты зелёные, тест red→green → `fixed`, коммит `fix(<id>): <кратко>`.
  - targeted-fix вернул «нужен дизайн» (новая структура/контракт → architecture-design) → статус
    `route:design`, причина, коммит (кода не менял). Следующий раунд возьмёт его в §2a.
  - «причина не держится / нужен триаж» (→ debugging-and-error-recovery) → `deferred:triage`, причина.
  - гейты красные после ретраев скила / правка не зашла 3× → откат (`git checkout -- <files>`),
    `fix-failed`, причина.
- Группу (§1) веди находка за находкой в одном раунде, ограничивая Verify каждой узкими тестами;
  полные гейты проекта — один прогон в конце раунда на весь диф группы.

## 2c. Маршрут `trivial` (сама)

- Внеси правку напрямую. Тронут исполняемый код — тот же один foreground-вызов
  `powershell -NoProfile -File ops/loop/gates.ps1` (таймаут 2700000 ms); чистые доки — гейты не нужны.
- Зелено → `fixed`, коммит `fix(<id>): <кратко>`. Что-то сломалось / оказалось поведенческим → откат,
  статус `route:fix` (следующий раунд закроет через targeted-fix).

## 3. Ледждер + коммит

- Строка в таблице `05-fixes.md`: `| F-ID | sev | route | status | commit | note |`. В `commit` — `—`
  (sha неизвестен до коммита; шаг находится по сообщению коммита).
- **Сообщение коммита** — как в §2a/§2b/§2c; для отложенного или провала —
  `debug(<id>): <status> — <кратко>`, только `05-fixes.md`; каталог `docs/audit/` git-ignored,
  поэтому индексируй реестр принудительно — `git add -f docs/audit/<пакет>/05-fixes.md`. Честный
  статус на исходе контекста — `fixed` / `fix-failed` / `route:*`.

## 4. Условие остановки

Каждая находка реестра числится `fixed` / `deferred:*` / `fix-failed` (промежуточные `designed` /
`route:*` — не финальные). Не осталось нерешённых → §5.

## 5. Финальный раунд (только при выполнении §4)

1. Сводка в `05-fixes.md`: сколько `fixed` (по маршрутам) / `deferred` (по классам) / `fix-failed`;
   перечень отложенного с причиной и рекомендованным воркфлоу.
2. Создай `docs/audit/<пакет>/DONE` с текстом `debug loop done: <F> fixed, <D> deferred, <X> failed`.
   Рабочую петлю он не трогает.
3. Коммит (§3), выйди.

## Жёсткие правила

Общий свод — `docs/loop/ROUND-COMMON.md`; здесь только то, что добавляет разбор находок.

- **Одна** единица работы за раунд: находка пути честности/Critical, группа §1 либо один шаг design/impl — шаг **целиком**, не milestone из его плана. Дефолт классификации — `targeted-fix`; `design` — только по структурному триггеру (§1).
- **Путь честности** закрывается только с пройденным `doubt-driven-development`.
- Маршрут «сама» — только для неповеденческих правок.
