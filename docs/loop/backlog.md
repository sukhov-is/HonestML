## Эпики

### EPIC-01 — Измеримая стоимость обучения

- **Состав:** наблюдаемая стоимость стадий и сопоставимый бенчмарк фиксированного рецепта и поиска с нуля; источник: дорожная карта, P0.
- **Требования:** строки ниже принадлежат EPIC-01; статусы и проверки — в матрицах срезов. Численные цели приёмки всей capability принадлежат EPIC-05.

| Тип / приоритет | Требование | Критерий приёмки | Источник |
|---|---|---|---|
| FR / must | Полное время обучения учитывается независимо от вложенных стадий | Непересекающиеся интервалы подготовки/FE, fingerprint, FS/HPO/CV, statistics и повторных refit/finalize вместе с явно выделенным overhead объясняют независимо измеренный total; вложенные интервалы не считаются дважды | P0; M5 FR-M5-4 |
| FR / must | Стоимость каждой единицы поиска видна в отчёте | По модели, FS-процедуре, trial/fold и ресурсу доступны время, число fit, rows/columns, tree budget и фактические iterations при поддержке backend | P0 |
| FR / must | Бенчмарк различает фиксированный рецепт и поиск с нуля | Есть отдельные сценарии с одинаковыми данными, split, параметрами и числом рефитов для сравниваемых сторон | P0; раздел 3 источника |
| NFR / must | Результат замера воспроизводим и интерпретируем | Manifest содержит версии, оборудование, CPU/RAM, данные, seed, границы timed-области и cold/warm; peak RSS и cache-hit привязаны к стадиям | P0 |
| NFR / must | Отчёт стоимости не раскрывает сырые корпоративные строки | Проверка схемы и содержимого отчёта подтверждает только агрегаты и идентификаторы контекста, без исходных значений строк | planning-discovered: локальная граница данных проекта |
| NFR / must | Новый замер не изменяет детерминированный honesty-baseline | Timing-результаты живут в отдельном контуре; действующий results-JSON без таймингов и его правила сохраняются | M9 FR-DLV-4, NFR-DLV-3 |

- **Зависимости:** внутренних нет; локальная наблюдаемость не зависит от корпоративных данных.
- **Блокеры:** BLK-1 ограничивает корпоративный замер и утверждение коэффициента скорости, но не локальный первый срез.
- **Драйверы и риски:** наблюдаемость должна охватить вложенные и повторные операции; риск неполной атрибуции — высокий по влиянию, вероятность уточняет первый замер. Контракт атрибуции описан в пакете training-cost-accounting.
- **Затронутые действующие требования:** `docs/architecture/automl-productionization/M5-orchestration-budget/01-requirements/FR.md` (FR-M5-4); `docs/architecture/automl-productionization/M9-delivery/01-requirements/NFR.md` (NFR-DLV-3/4). Существующая отчётность расширяется; требования прошлых пакетов здесь не переписываются.
- **Срез `EPIC-01-cost-accounting` (◐):** Полная стоимость обучения. `docs/architecture/training-cost-accounting/`

### EPIC-02 — Единый смысл параметров HPO и финального обучения

- **Состав:** корректность числа деревьев в objective, оценке и поставляемой модели; источник: дорожная карта, P1. Это согласование действующего HPO с early stopping.
- **Требования:** строки ниже принадлежат EPIC-02; статусы и проверки — в матрицах срезов.

| Тип / приоритет | Требование | Критерий приёмки | Источник |
|---|---|---|---|
| FR / must | Координата числа деревьев HPO имеет действующий смысл | Воспроизводящая проверка фиксирует фактические параметры backend; неработающая координата исключена или получает действующий смысл | P1; FR-HPO-3 |
| FR / must | Финальный refit использует обоснованное правило числа итераций | Для каждого поддерживаемого boosting backend прослеживается происхождение tree count из DEV и его применение в refit | P1 |
| NFR / must | Выбор iterations не использует итоговую контрольную выборку | Проверка доступа к строкам подтверждает отсутствие holdout в выводе tree count | P1; NFR-M7-3 |
| NFR / must | Результат воспроизводим при фиксированном вычислительном бюджете | Одинаковые данные/seed/ресурс дают одинаковое решение; wall-clock режим раскрывает иной контракт | NFR-M7-2; P1 |

- **Зависимости:** исходное воспроизведение выполняется самостоятельно; оценка изменения времени использует EPIC-01.
- **Блокеры:** нет для проверки расхождения и проектирования исправления.
- **Драйверы и риски:** изменение правила iterations может изменить качество и поставляемые модели; влияние высокое, вероятность/величина требуют регрессии. Контракт iterations описан в пакете training-iteration-contract.
- **Затронутые действующие требования:** `docs/architecture/automl-productionization/M7-hpo-ensembling/01-requirements/FR.md` (FR-HPO-3/4/6), `docs/architecture/automl-productionization/M7-hpo-ensembling/01-requirements/NFR.md` (NFR-M7-2/3); `docs/adr/ADR-0080-boosting-early-stopping.md`. Готовый HPO-порт не создаётся повторно.
- **Срез `EPIC-02-iteration-contract` (◐):** Итерации HPO, ES и refit. `docs/architecture/training-iteration-contract/`

### EPIC-03 — Переиспользование дорогих стадий

- **Состав:** точный реюз subset-оценок внутри запуска и завершённых FS/HPO-вычислений между запусками; источник: P2/P3. Первый результат — локальный FS-реюз; persistent HPO-resume не задерживает холодный быстрый поиск.
- **Требования:** строки ниже принадлежат EPIC-03; статусы и проверки — в матрицах срезов.

| Тип / приоритет | Требование | Критерий приёмки | Источник |
|---|---|---|---|
| FR / must | Идентичная FS-оценка использует ранее полученные score/OOF/mask | Повтор trajectory/band/gate при совпадающем контексте не увеличивает число fit | P2 |
| FR / should | Повтор идентичного запуска восстанавливает завершённые FS/HPO-стадии до их исполнения | Warm-run имеет ноль повторных завершённых поисковых fit; финальное обучение учитывается отдельно | P3 |
| FR / should | Прерванный HPO продолжается с учётом состояния поиска | Для фиксированного ресурса resumed-run соответствует непрерывному по принятому контракту; незавершённое не объявлено завершённым | P3 |
| NFR / must | Кеш не меняет статистический результат | При точном реюзе совпадают subset, score, OOF-mask и tie-break; time-budget различия явно раскрыты | P2/P3; NFR-RC-2 |
| NFR / must | Несовместимый вычислительный контекст исключает cache-hit | Изменение данных/порядка фич/folds/преобразований/весов/seed/модели/ресурса/значимой версии вызывает пересчёт; неопределённость означает miss | P2/P3; NFR-RC-1 |
| NFR / must | Объём кеша ограничен | Нет обязательного хранения всех O(p²) OOF; измеренный объём укладывается в выбранный memory limit | P2/P3; порог памяти EPIC-03 |
| NFR / must | Прерванная запись не выглядит завершённой | Частичная или несовместимая запись даёт miss; состояние sampler проверяется до продолжения | planning-discovered: расширение NFR-RC-1/4; P3 |

- **Зависимости:** EPIC-01 для измерения выигрыша; HPO reuse зависит от EPIC-02. Первый FS-срез независим от HPO-resume. Изменение search-policy в EPIC-04 учитывается в зависимостях кеша.
- **Блокеры:** нет для локального FS-реюза; выбор гранулярности и формата записи относится к дизайну, не к вопросу доступа.
- **Драйверы и риски:** ошибочный hit даёт неверный результат (высокое влияние, вероятность проверяется инвалидационными тестами); полное хранение OOF может исчерпать RAM. Вычислительные ключи и восстановление описаны в пакетах training-subset-reuse и training-stage-resume.
- **Затронутые действующие требования:** `docs/architecture/automl-productionization/M5-resume-stage-cache/01-requirements/FR.md` (FR-RC-1/2/3/5/6 и граница per-candidate); `docs/architecture/automl-productionization/M5-resume-stage-cache/01-requirements/NFR.md` (NFR-RC-1/2/4/6/7); NFR-M7-2. Публичный cache-API и candidate cache уже существуют; пересматриваются зависимости ключей и гранулярность.
- **Срез `EPIC-03-subset-reuse` (◐):** Повторное использование FS-оценок. `docs/architecture/training-subset-reuse/`
- **Срез `EPIC-03-stage-resume` (◐):** Возобновление FS и HPO. `docs/architecture/training-stage-resume/`

- **Дополнительные ограничения FS:** `docs/architecture/automl-productionization/M6-feature-engineering/M6c-feature-selection-compare/01-requirements/FR.md` (FR-FSC-3/4/7) и `NFR.md` (NFR-FSC-3/5), `docs/architecture/adaptive-cascade-sizing/01-requirements/FR.md` (FR-1/2) и `NFR.md` (NFR-1/2/3) сохраняются при точном реюзе; это владельцы проверок эквивалентности FS.

### EPIC-04 — Быстрый выбор алгоритма и процедуры FS в бюджете

- **Состав:** ограниченные предварительные пробы, выбор одного семейства и одной FS-процедуры, исполнение выбранной комбинации с резервом на завершение; источник: P4/P5/P6. Одна FS-процедура может включать несколько последовательных этапов отбора; предварительный выбор сравнивает такие рецепты целиком.
- **Требования:** строки ниже принадлежат EPIC-04; статусы и проверки — в матрицах срезов. Порог качества и профиль оценки связаны с BLK-2; численные ступени ресурса остаются proposed.

| Тип / приоритет | Требование | Критерий приёмки | Источник |
|---|---|---|---|
| FR / must | Алгоритмы сначала сравниваются на ограниченном ресурсе | Исключённые семейства не доходят до максимального ресурса; конфигурации и причины продвижения отражены в отчёте | P4 |
| NFR / must | Предварительное сокращение ширины не исключает алгоритм из-за слепоты proxy | Проверки с нативным категориальным и распределённым сигналом подтверждают защиту до отсева семейства; результат сопоставлен с ограниченной широкой пробой; конкретный механизм задаёт дизайн | P4; раздел 4 источника; профиль качества BLK-2 |
| FR / must | Явно заданный единственный алгоритм пропускает автоматический выбор | Нет scouting-fit; выбор пользователя сохранён | P4; действующий models API |
| FR / must | Полноценный HPO получает только выбранное семейство | После фиксации алгоритма остальные не тюнятся; отсутствие HPO допустимо по явной конфигурации | P4 |
| FR / must | Процедура FS выбирается до дорогого исполнения всех вариантов | Отсечённые процедуры используют предварительный ресурс; на максимальном исполняется одна, широкий контроль учитывается отдельно | P5 |
| FR / must | FS-финалисты подтверждаются выбранным алгоритмом | Есть ограниченная проверка subset и сопоставимый широкий контроль; при ухудшении применяется заранее определённый fallback | P5 |
| FR / must | Неоднозначность выбора имеет ограниченный исход | Ресурс увеличивается только в допустимых пределах; ничья или недостаток данных приводят к документированному решению, без скрытого полного перебора | P4/P5 |
| FR / must | Сбой предварительной пробы имеет явный исход | Для ошибочного кандидата и случая без пригодных кандидатов проверяются причина, состояние результата и предусмотренный отказ либо fallback; неполная оценка не объявлена успешной | planning-discovered: полнота отказов ограниченного поиска |
| FR / must | Общий бюджет оставляет ресурс на обязательное завершение | До дорогих стадий имеется опорный результат; checks между единицами работы сохраняют резерв оценки/refit; причина остановки видна | P6 |
| NFR / must | Sampling и поиск сохраняют границы данных | Проверки train/ES/validation, времени, групп, горизонта таргета, encoding и весов исключают запрещённые строки; редкий класс не теряется молча | P4/P5; раздел 4 источника |
| NFR / must | Оценки разных ресурсов и полноты не выдаются за сопоставимые | Неполный CV не конкурирует как полный; post-search OOF обозначен; независимая оценка соответствует выбранному профилю BLK-2 | P4/P6 |
| NFR / must | Финальная модель использует всю предусмотренную train-часть | Лимит поисковой выборки не переносится скрыто в final fit | P5 |
| NFR / must | Память поисковых стадий соблюдает выбранный лимит | Измеренный RSS и поведение на границе соответствуют действующему memory-limit контракту | P6; порог памяти EPIC-04 |
| NFR / must | CPU используется без вложенной переподписки | Согласованный лимит потоков соблюдён одновременно выполняемыми стадиями и backend | P6 |
| NFR / must | Превышение кооперативного времени раскрыто | Отчёт содержит фактическое время, границу остановки и overshoot; жёсткий deadline не обещан | P6; NFR-M5-1 |
| NFR / must | Поиск воспроизводим при фиксированном ресурсе | Одинаковый контекст даёт одинаковые пробы/решения; отдельный контракт для wall-clock budget | NFR-M5-2, NFR-M7-2; P4/P6 |

- **Блокеры:** BLK-2 — принятие требований к качеству и независимости оценки для продуктовой приёмки поисковой политики; BLK-1 — численные цели производительности до корпоративной приёмки. Изучение вариантов и локальные пробы доступны до закрытия этих вопросов.

Влияние высокое; вероятность оценивается на корпусе. Контракт ограниченного поиска и бюджета описан в пакетах training-bounded-search и training-completion-budget; численные приёмки открыты.

### EPIC-05 — Подтверждённое ускорение и пользовательский путь

- **Состав:** приёмка холодного поиска и повторов на реальном сценарии, понятная конфигурация быстрого обучения; источник: P7 и разделы 3/6 дорожной карты.
- **Требования:** строки ниже принадлежат EPIC-05; статусы и проверки — в матрицах срезов. Общие численные NFR приведены в разделе «Пороги и решения».

## Осознанные исключения

- HPO, candidate cache, cascade FS, native categories, early stopping и простой выбор `models=(...)` уже существуют; новая работа расширяет их по указанным границам.
- Ускорение через ослабление независимости оценки, удаление широкого контроля или скрытое сокращение final train не входит в план.
- Новый AutoML-backend, внешняя зависимость, обязательный ансамбль, GPU/distributed-переписывание и параллельный исчерпывающий перебор не требуются для первой версии быстрого пути.
- Жёсткое прерывание нативного fit не входит в обязательства первой версии; обещается только согласованный и наблюдаемый кооперативный бюджет. Расширение требует отдельного решения.
- Архивные изменения действующих пакетов и их завершённые срезы не переносятся в новый backlog как несделанная работа. Их требования здесь только названы как ограничители/кандидаты пересмотра.
- Persistent HPO-resume и регулярное переобучение сохранённого рецепта имеют приоритет should; они не блокируют поставку проверенного холодного быстрого поиска. Полный исследовательский сценарий остаётся доступным.

## Planning-discovered дополнения

- EPIC-01/05: среда и границы замера входят в provenance; агрегированные отчёты не содержат строки корпоративных данных. Основание — воспроизводимость сравнения и локальная граница данных проекта.
- EPIC-03: прерванная запись и несовместимое состояние sampler различаются с завершённым поиском; неизвестная совместимость означает пересчёт. Основание — полнота отказов при расширении NFR-RC-1/4.
- EPIC-04: при недостатке классов/периодов или сбое кандидата исход ограниченной пробы раскрывается; частичный CV не получает видимость полной оценки. Основание — полнота деградации нового поиска.
- EPIC-05: именованные AP и трапецеидальная PR-AUC считаются отдельно; исторические метрики не приписываются текущему ручному рецепту. Основание — сопоставимость независимой приёмки.
