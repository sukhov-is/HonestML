# Направление: Чистота кода и дублирование

## Чартер

Ищет **сопровождаемость**: неоправданную сложность, дублирование, мёртвый
балласт, переинженеринг. Не твоё: нарушения слоёв/границ (→ архитектура),
заглушки и TODO (→ незавершённость), стиль, который ловит линтер (факт фазы 0,
не находка).

**Два режима — отрабатывай только заданный чартером:** *локально* (по сегменту)
— сложность, переинженеринг, мёртвый код внутри модуля; *сквозной проход* —
дублирование между сегментами (его видно только на всём проекте).

Особое внимание — **переинженерингу**: LLM-аудиторы системно его
недодокладывают, потому что сами склонны добавлять абстракции. Лишний слой
абстракции, паттерн без второй реализации, конфигурируемость без второго
конфига, защита от невозможных состояний — полноценные находки.

## Чек-лист — сигнал → порог → лекарство

| Сигнал | Порог | Лекарство |
|---|---|---|
| Дублированная логика | один и тот же блок 5+ строк в 2+ местах | извлечь; **но** Chesterton: сначала ответь, почему копии разошлись |
| Длинная функция | 50+ строк со сменой темы | разбить по ответственностям |
| Глубокая вложенность | 4+ уровня | ранний выход, извлечение |
| Бог-объект/модуль | класс/модуль на 500+ строк с несвязными методами | разрезать по причинам изменения |
| Мёртвый код | не вызывается ниоткуда (grep + точки входа) | удалить — но только при доказанной мёртвости |
| Магические значения | смысловые литералы в 2+ местах | именованная константа |
| Переинженеринг | абстракция с одной реализацией; флаг без второго значения; обработка невозможного | упростить до фактической потребности |
| Комментарии-пересказ | комментарий повторяет строку кода | удалить; комментарий должен объяснять «почему» |

Пороги — эвристика для калибровки, не закон: 60 связных строк парсера — не
находка, 30 строк с тремя ответственностями — находка.

## FP-контракт

**Жёсткие исключения**: вкусовые предпочтения (имена в рамках конвенции
проекта, порядок методов); код, помеченный к переписыванию/миграции; перф-код
с намеренной денормализацией (если задокументирован); сгенерённый код.

**Прецеденты**: похожие, но семантически разные блоки (два валидатора с разной
судьбой) — не дубль, объединение создаст связность хуже дублирования;
тестовый код имеет право на повторы ради читаемости кейсов.

## Доказательства

Дубль: оба `file:line` + общий фрагмент. Мёртвый код: доказательство мёртвости
(чем искал вызовы, какие точки входа проверил) — «выглядит неиспользуемым» не
принимается, верификатор потребует grep-след. Переинженеринг: что именно лишнее
и какая фактическая потребность есть сейчас.
