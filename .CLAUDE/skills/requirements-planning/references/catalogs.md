# Каталоги плана: формат, основания, гейт

Форматная часть планирования: как выглядит запись backlog, чем обосновано число
в NFR, что засчитывает requirements-gate. Читай перед фазами 3 и 8; в bootstrap —
перед созданием каркаса.

## 1. Формат записи

Состав полей FR и NFR берётся из шаблонов пакета:
`../../architecture-design/assets/FR.template.md` и `NFR.template.md`. Плановая
запись добавляет к ним ровно следующее:

- **носитель** — эпик, в составе которого требование живёт до нарезки среза;
  стабильные `FR-N`/`NFR-N` даёт пакет среза, глобального пространства ID нет;
- **приоритет** `must / should / could` — атрибут записи; очередь выбора
  работы задаёт порядок строк `## Сводка`;
- **перекрёстные ссылки** FR ↔ NFR: числа и пороги живут в NFR, FR на них
  ссылается;
- при расхождении FR и NFR авторитетен **NFR**;
- нерешённое требование помечается `proposed` с указанием, какого решения не
  хватает.

В режиме дельты «шаблон» — сам backlog: новая запись неотличима по стилю от
соседних, а конвенция файла старше этого текста.

## 2. Драйверы, backlog, порядок

- **Драйверы** — то, что формирует структуру (не всё из требований влияет на
  архитектуру): ссылка на источник FR/NFR, «почему формирует структуру», ссылка
  на ADR или `TODO`; в плане они живут полями эпика, оформляет их срез. Риски —
  вероятность × влияние плюс реакция.
- **Backlog** (`docs/loop/backlog.md`) — навигатор статуса поверх требований, не
  их замена; его грамматику судит `ops/loop/check_registers.py`. Одна сетка:
  шапка (легенда, квитанции `Requirements gate`, счётчик
  `Всего эпиков: **N** · done: **a** · partial: **b** · todo: **c**`) →
  `## Сводка` (таблица `Эпик | Результат | Требования | Статус |
  Осталось | Блокеры`; порядок строк — приоритет выбора работы; ячейки «Осталось»
  и «Блокеры» до 200 символов и без хроники) → `## Эпики` с секциями
  `### EPIC-NN — название` и обязательными полями `**Состав:**`,
  `**Требования:**`, `**Зависимости:**`, `**Блокеры:**` →
  `## Осознанные исключения` → `## Planning-discovered дополнения`.
  Записи внутри эпика: `- **Срез `ID` (статус):** outcome одной фразой; зависимость;
  `docs/architecture/<pkg>/`` — статус из закрытого словаря ☑ · ◐ · ☐ · ⛔ BLK-n |
  `id` · ⏸ решение · ✂ решение, тело до 400 символов без хроники (раундов, тестов,
  ADR, ревью); `- **Кандидаты (не выбираются):**` с вложенными `` - `id` — суть;
  источник: …; закрывает: FR/NFR | — `` (кандидат — регистрация, не задание);
  `- **Отложено (⏸ решение, дата):**` с вложенными `` - `id` — суть ``; запись
  кандидата и отложенного — до 300 символов, внутри раунда петли — не больше
  трёх новых кандидатов на пакет. Пакеты описывают **target**-дизайн, живой
  статус реализации принадлежит backlog и модульным матрицам срезов.
- **Порядок** — очередь выбора работы задаёт порядок строк `## Сводка`, связи
  между эпиками — поле `**Зависимости:**` их секций; календаря нет.

## 3. Пробелы источника

Спека всегда что-то упускает; различай тип пробела. **Продуктовый** — меняет
наблюдаемое поведение или scope, возвращай в спеку. **Пробел полноты требований** —
отказы, деградация, совместимость, лимиты, не меняющие продуктовый контракт, —
закрывай сам с пометкой `planning-discovered` в поле источника; на
requirements-gate такие дополнения показываются отдельным списком.

## 4. Основания NFR

Свойства, которыми меряется библиотека: детерминизм и воспроизводимость прогона;
честность оценки и отсутствие утечки; бюджеты времени и памяти; совместимость
публичного API и версионирование; переносимость артефактов между средами;
качество диагностики отказа. Требование вне этих классов сначала объясни, потом
заводи.

Каждое число и порог имеет именованное основание:

- критерий спеки;
- согласованность с соседними NFR действующих пакетов — новый порог не должен
  молча требовать от общего пути больше, чем действующий;
- внешнее ограничение как факт: поддерживаемые версии Python, лицензия и
  доступность зависимости, границы формата экспорта (из research);
- деривация из родительского бюджета: сумма под-бюджетов не превышает бюджет
  прогона;
- индустриальный прецедент.

Нет основания — ставь `proposed` с указанием, какого решения или замера не хватает.
Честный `proposed` лучше выдуманного числа с авторитетным видом; закроет его
spike или бенчмарк в срезе.

## 5. Чек-лист requirements-gate (фаза 8)

Гейт закрыт, когда — по свидетельствам этой сессии:

- [ ] каждый новый FR/NFR атомарен, с критерием приёмки, приоритетом и ссылками;
- [ ] у каждого нового FR есть эпик-носитель; у каждого нового NFR — носитель:
      эпик(и) или сквозная дорожка;
- [ ] дельта не дублирует существующих требований (подтверждено ревью);
- [ ] пересмотры существующих показаны пользователю как явная дельта;
- [ ] блокеры и зависимости эпиков именованы, порядок строк сводки отражает
      очередь выбора работы;
- [ ] счётчик эпиков и шапка backlog сходятся со сводкой;
- [ ] `uv run python ops/loop/check_registers.py` зелёный на текущем дереве;
- [ ] находки ревью закрыты или приняты с диспозицией.
