# Отчёты, roadmap, повторный аудит (фаза 4)

## 03-summary.md — сводный отчёт

Структура (выдерживай порядок — читатель идёт от вердикта к деталям):

```markdown
# Аудит <проект/scope> — <дата>

## Вердикт
<2–4 предложения: общее состояние, главный риск, главный долг. Без жаргона
сессии — для читателя, который не видел работы.>

## Здоровье по направлениям
| Направление | Вердикт | Critical | High | Medium | Low/Info |
|---|---|---|---|---|---|
<вердикт clean/issues/blocked по подтверждённым находкам>
<непокрытые направления — отдельной строкой «не аудировалось»>

## Топ-находки
<5–10 самых важных подтверждённых, по схеме находки, severity по убыванию>

## Что солидно
<3–7 пунктов: что в проекте сделано хорошо, с конкретикой. Калибрует severity
и доказывает, что аудитор читал здоровый код, а не только искал проблемы>

## Динамика (re-audit)
закрыто N / осталось M / новых K; направления с ухудшением

## Приложение: отклонённые находки
<таблица из реестра — id, заголовок, причина. Строит доверие к фильтру>
```

Каждая строка сводки прослеживается до записи `02-ledger.md` или вывода
инструмента из `00-inventory.md`. Пункт без свидетельства в отчёт не идёт.
Числа (сколько найдено/подтверждено/отклонено/понижено) бери **прямым подсчётом
строк реестра**, не по памяти: расхождение счётчиков с таблицами подрывает
доверие ко всему отчёту.

## Здоровье направления

Направление описывается вердиктом `clean | issues | blocked` и счётчиками подтверждённых
находок по severity. Этого хватает и для чтения, и для сравнения аудитов: динамика видна
по счётчикам, а один Critical виден сразу и не растворяется в средней оценке.

## 04-roadmap.md — план улучшений

Эффорт-бакеты, внутри — по severity. Каждый пункт = находка(и) из реестра +
маршрут:

```markdown
## Быстрые победы (<30 мин каждая)
- [ ] <заголовок находки> (id, sev) → fix-prompt из находки

## Средние (30 мин – 2 ч)
- [ ] … → скил: debugging-and-error-recovery / implementation

## Комплексные (>2 ч, системные)
- [ ] … → скил: architecture-design (перестройка) / spec-driven-development
      (недоспецифицированный функционал)

## Не делать сейчас (осознанно отложено)
- <находка> — причина откладывания
```

Маршрутизация — рекомендация, не запуск: audit-gate означает, что фиксы
начинаются только по решению пользователя.

## Повторный аудит — staleness и learnings

**Сверка прошлого реестра** (до нового fan-out): для каждой прошлой
подтверждённой находки проверь по текущему коду — `исправлена` (кода с цитатой
больше нет, поведение изменено) / `актуальна` (цитата на месте) / `устарела`
(файл переписан, якорь потерян → перепроверь заново или закрой с пометкой).
Не доверяй заявлению «починили» без чтения кода.

**learnings.md** — подавления, накопленные от пользователя:

```markdown
- паттерн: <что не флагать — сигнатура/путь/правило>
  scope: <где действует>
  причина: <почему это намеренно> (дата, кто решил)
```

Пиши сюда только явные решения пользователя («это намеренно», «не флагай
такое»), не свои выводы. Аудиторы получают learnings в чартере; верификаторы —
нет (иначе подавление маскирует регрессию: намеренный компромисс мог
протухнуть — пусть TRADE-OFF переподтверждается).
