# Архитектурные драйверы и риски — <Feature>

> Драйверы — то, что реально формирует структуру (не всё из требований влияет на
> архитектуру). Риск-реестр — что может пойти не так и что с этим делаем. Вместе
> они обосновывают ADR.

## Архитектурные драйверы

| ID | Драйвер | Тип | Источник (FR/NFR) | Почему формирует структуру |
|----|---------|-----|-------------------|----------------------------|
| D-1 | <напр.: срез укладывается в бюджет прогона на 200k×80> | критичный NFR | NFR-1 | <диктует ранний отсев кандидатов + кэш стадий> |
| D-2 | <ключевой сценарий: honest holdout не видит отбор признаков> | сценарий | FR-1 | <отдельный путь нарезки до селекции> |
| D-3 | <ограничение: core не зависит от ML-библиотек> | ограничение | NFR-2 | <требует порта и адаптера> |

Типы драйверов: критичный NFR · ключевой сценарий · техническое ограничение ·
бизнес-ограничение · допущение.

## Риск-реестр

| ID | Риск | Вер. | Влияние | Реакция | Spike? |
|----|------|------|---------|---------|--------|
| R-1 | <напр.: экспорт в ONNX не даёт паритета предсказаний для семейства X> | средн. | высок. | mitigate → POC | SPIKE-0001 |
| R-2 | <совместимость `ModelArtifact` при смене формата> | низк. | высок. | mitigate → план миграции | — |
| R-3 | <…> | | | accept / avoid / transfer | |

- **Вероятность / Влияние:** низк. / средн. / высок.
- **Реакция:** mitigate (снизить) · accept (принять) · avoid (избежать) ·
  transfer (передать).
- Риск с **высокой неопределённостью и высоким влиянием** → заведи spike (фаза 4)
  *до* фиксации связанного ADR.
