# HonestML Autonomous Loop

Петля по кругу: **спроектировать срез → реализовать → обновить бэклог**, без человека в каждом раунде.
Драйвер сам работу не делает — он только перезапускает свежий процесс-воркер, который выполняет один
раунд по контракту [`docs/loop/LOOP.md`](../../docs/loop/LOOP.md). Свежий процесс на раунд = чистый
контекст: окно не кончается, сколько бы раундов ни было. Преемственность — в файлах и git, не в памяти.

## Запуск Claude

```powershell
# 1) СНАЧАЛА супервизируемый прогон одного раунда — посмотреть, что петля делает:
powershell -NoProfile -ExecutionPolicy Bypass -File ops/loop/ralph.ps1 -SkipPermissions -MaxIterations 1

# 2) затем автономный прогон до STOP / блокеров / нарушения контракта impl-раунда:
powershell -NoProfile -ExecutionPolicy Bypass -File ops/loop/ralph.ps1 -SkipPermissions
```

`-SkipPermissions` передаёт `claude --dangerously-skip-permissions` — без него headless-раунд
зависнет на запросе разрешений. **Это значит, что петля автономно правит код, гоняет команды и
коммитит без подтверждений.** Поэтому: сначала один супервизируемый раунд, репозиторий под git
(откат пораундовый), запускайте только когда готовы к автономии.

**Все раунды идут на `claude-opus-5[1m]` — 1M-контекст.** Тип раунда драйвер определяет по гроссбуху
до запуска процесса и фиксирует на весь раунд: design держит в окне весь пакет, implementation —
рекомендованный срез на 25–75 тестов вместе с его ревью, не упираясь в компакцию к концу раунда.
Диапазон помогает нарезке, но не блокирует связный outcome другого размера. Оба — `--effort high`.
Fan-out субагенты (research/review) принудительно идут на `claude-opus-5[1m]` через
`CLAUDE_CODE_SUBAGENT_MODEL`; `-SubagentModel ''` снимает override.

Одна модель на все раунды: `-Model claude-opus-5 -Effort high` (single-режим включается самим фактом
передачи `-Model`). Модель задаётся явно всегда — иначе headless берёт сохранённый дефолт.
Fast-режим (`/fast`) в headless недоступен.

## Запуск Codex

Оба драйвера используют один контракт `LOOP.md`, гроссбух и навыки проекта. Codex-драйвер запускает
для каждого раунда отдельный сохраняемый поток `codex exec`; контекст между раундами не переносится.
Если model turn завершился раньше repository-контракта раунда — остался незакрытый command,
нет коммита, дерево грязное или IMPLEMENT не `done`/`blocked` — драйвер делает `exec resume` того же
потока. Все сегменты делят единый лимит `-MaxRoundMinutes`.

Claude-драйвер возобновляет по одному признаку: раунд вышел с кодом 0, но коммита не оставил.
Тогда он один раз делает `claude --resume` той же сессии с указанием доделать раунд по `LOOP.md §5`
и перепроверяет HEAD; второй пустой результат — настоящий no-progress stall, петля встаёт. Типичная
причина такого раунда — ход, законченный до вердикта DoD: выход процесса убивает его же фоновую
задачу. Возобновление переиспользует контекст раунда и стоит доли его цены. Транспортный сбой
(ненулевой код, оборванное соединение, 5xx) обрабатывается отдельно — тем же раундом на его WIP,
до `-MaxTransientRetries` подряд.

```powershell
# безопасные проверки; модель не запускается, STOP можно оставить на месте
powershell -NoProfile -ExecutionPolicy Bypass -File ops/loop/ralph-codex.ps1 -SelfTest
powershell -NoProfile -ExecutionPolicy Bypass -File ops/loop/ralph-codex.ps1 -Preflight

# после проверки и коммита обвязки: один супервизируемый раунд
Remove-Item docs/loop/STOP
powershell -NoProfile -ExecutionPolicy Bypass -File ops/loop/ralph-codex.ps1 `
  -BypassPermissions -MaxIterations 1

# затем автономно до STOP / блокеров / нарушения контракта impl-раунда
powershell -NoProfile -ExecutionPolicy Bypass -File ops/loop/ralph-codex.ps1 -BypassPermissions
```

По умолчанию design- и implementation-раунды используют `gpt-6-astra` с `medium` effort. Переопределение
для всех раундов: `-Model <model> -Effort medium`. `-BypassPermissions` разрешает агенту без подтверждений править код,
выполнять команды, доверять проектным хукам и коммитить — запускайте только в чистом отдельном checkout.
Ненулевой код CLI, `turn.failed`, отсутствие terminal JSONL или общий таймаут (`-MaxRoundMinutes`,
по умолчанию 400) останавливает петлю с ненулевым кодом (`124` для таймаута) и сохраняет WIP.
`turn.completed` завершает только текущий сегмент; весь раунд завершает repository-контракт и коммит.
Одновременно Claude- и Codex-драйверы не запускайте:
они меняют одни и те же файлы состояния и git-ветку.

## Остановка / мониторинг

- **Стоп:** `New-Item docs/loop/STOP` (мягко: раунд доделывается и коммитится, петля встаёт перед следующим) ·
  `New-Item docs/loop/STOP-NOW` (Codex: немедленный кил процесса раунда, WIP остаётся) · `Ctrl-C` (жёстко).
- **Прогресс:** итог — `docs/loop/state.md` (гроссбух) и `git log --oneline` (коммит на раунд).
  Live-ход раунда: консоль драйвера (читаемые события из stream-json/JSONL) или хвост последнего лога
  `Get-Content (Get-ChildItem ops/loop/logs/*.out | sort LastWriteTime)[-1] -Wait -Tail 5`.
- **Telegram:** оба драйвера шлют уведомление после каждого раунда (номер, тип, статус, длительность,
  subject коммита, а у раунда, тронувшего код, — ещё строка `lines:` с добавленными и удалёнными
  строками в `src` и `tests` против текущего размера этих деревьев; числа драйвер снимает с git)
  и при каждой остановке — stall, повтор subject коммита, лимит, таймаут раунда (Codex), STOP,
  blocked-only, нарушение протокола, падение самого драйвера. Настройка: впишите токен бота и
  chat_id в `ops/loop/notify.json` (git-ignored — `git clean` восстановления раунда его не уносит).
- **Вопросы к вам:** `docs/loop/blockers.md` — ответьте и смените `open` → `answered: <решение>`.
- **Откат раунда:** `git revert <sha>` (sha из гроссбуха, либо
  `git log --grep "loop(<item>)" -1 --format=%H`) или `git reset --hard <sha-предыдущего>`.

Авто-стоп: файл `STOP` · `-MaxIterations` · последний раунд `blocked-only` (готовой работы не осталось) ·
сброс лимита дальше `-MaxWaitHours` · нарушение контракта implementation-раунда. Implementation-раунд
исправляет замечания review в том же процессе и может завершиться только `done` или внешним `blocked`;
новый `needs-fix` блокируется hook-guard и считается ошибкой протокола.

## Лимиты токенов (5h / недельные)

Headless `claude -p` ест из **того же** пула подписки, что и интерактив — петля упрётся в лимит.
Встроенного «ждать до сброса» у Claude Code нет, поэтому драйвер делает это сам:

1. Ловит в выводе сообщение лимита (`hit your session/weekly limit · resets …`).
2. **Оставляет WIP раунда в дереве.** Лимит — это пауза, а не вердикт о работе: незакоммиченные
   файлы раунда никуда не деваются.
3. Парсит время сброса, **спит до него + `-BufferMinutes`** и **продолжает тот же раунд**:
   claude-драйвер поднимает `--resume` ту же сессию, чтобы раунд знал, что делал, а не начинал
   заново поверх своих же половинчатых файлов. Провалом раунда это не считается.
4. Если время сброса не распарсилось — ждёт `-DefaultBackoffMinutes` (30 мин), и каждое
   следующее слепое ожидание **удваивается**. После `-MaxBackoffRetries` (4) подряд драйвер
   останавливается: стена, которая отвечает одинаково, не пробивается повторами.

**5-часовой лимит** покрывается автоматически (ожидание обычно ≤ нескольких часов).
**Недельный лимит** обычно дальше `-MaxWaitHours` (default 6): драйвер не висит сутками, а
**выходит чисто**, напечатав время сброса. Возобновление после длинного окна — планировщиком:

```powershell
# относительный возобновитель: пробуждать драйвер каждый час; он сам выйдет, если лимит ещё держится,
# и доработает, когда окно откроется. Запуск под текущим пользователем.
$action  = New-ScheduledTaskAction -Execute 'powershell' `
  -Argument '-File C:\Users\Admin\Documents\AutoML\ops\loop\ralph.ps1 -SkipPermissions' `
  -WorkingDirectory 'C:\Users\Admin\Documents\AutoML'
$trigger = New-ScheduledTaskTrigger -Once -At (Get-Date).Date.AddHours(1) `
  -RepetitionInterval (New-TimeSpan -Hours 1)
Register-ScheduledTask -TaskName 'honestml-loop' -Action $action -Trigger $trigger
# снять: Unregister-ScheduledTask -TaskName 'honestml-loop' -Confirm:$false
```

Параметры тюнинга драйвера: `-MaxWaitHours`, `-BufferMinutes`, `-DefaultBackoffMinutes`,
`-MaxTransientRetries`, `-Force` (стартовать с грязным деревом). См. шапку `ralph.ps1`.
Драйвер по умолчанию выставляет `CLAUDE_CODE_RETRY_WATCHDOG=1` (бесконечный ретрай 429/529:
транзиентный перегрев сервера ретраится внутри раунда, а не роняет петлю ненулевым выходом; это
**не** ожидание окна лимита). Переопределить — заранее выставить переменную в окружении. Смежное:
`CLAUDE_CODE_MAX_RETRIES`.

Обрыв соединения или 5xx убивает сам процесс раунда — это переживает уже драйвер (**оба**,
`ralph.ps1` и `ralph-codex.ps1`): он перезапускает **тот же** раунд, сохраняя его WIP на диске
(свежий процесс — у Codex ещё и свежий поток — продолжает от файлов), до `-MaxTransientRetries` раз
подряд (по умолчанию 3); счётчик обнуляется после успешного раунда. Логи неудачных попыток остаются
рядом с суффиксом `-tN`. Ошибка содержательного уровня (неверный запрос, нарушение протокола раунда)
и упёртый лимит транзиентными не считаются и по-прежнему останавливают петлю.

## Альтернатива: плагин `ralph-loop` (in-session)

`/ralph-loop` крутит петлю **внутри текущей сессии** (stop-хук скармливает промпт обратно в тот же
контекст). Контекст при этом **накапливается** — годится посмотреть один-два раунда вживую, но для
длинного автономного прогона используйте внешний драйвер выше (свежий контекст на раунд).
